Project alignment: 3A Market Research Agent — Competitor Analysis

Public code: github.com/ak-55-lab/intellia-competitive-intel

Author: Akash Kamineni

1. Product overview

Intellia turns public web evidence into source-linked competitive intelligence for sellers. A user enters a focal-company website, chooses one to ten competitors, and receives a company-specific signal graph, evidence matrix, battlecards, retrieval traces, regional context, and Ask Intellia follow-up answers.

Scope: external, public information only. Intellia does not access CRM data, calls, private files, employee data, or customer records.

3. Multi-agent architecture

Intellia is a deterministic, typed multi-agent harness. Each agent has a bounded role, passes state to the next agent, and is stopped by a quality gate rather than an unconstrained model loop.

5. Quality, safety, and reliability controls

ControlProduction behavior
Discovery qualityRequires cited search evidence, a non-directory official-looking domain, and retrieved homepage brand confirmation.
Evidence gateRequires focal and competitor evidence, at least six distinct substantive sources, three source types, and regional evidence.
Deep research qualityRequires at least two returned URL citations; uncited output is excluded.
Claim integrityExtraction is constrained to supplied evidence; each claim must reference a collected source ID.
QA rubricScores 0–100 across evidence depth/diversity/authority, claim attribution, seller usefulness, and usability. Publication requires 70+ with no blocking issue.
Provider resilienceFirecrawl is globally paced for the configured plan, honors Retry-After, and retries documented transient failures with jitter.
Operational behaviorInteractive requests return immediately as collecting; the always-on service finishes the run, persists it, and the UI reloads the completed result.

6. Technology stack and rationale

LayerTechnologyWhy selected
End-to-end applicationTypeScript, Next.js 15, React 19One typed language for UI, APIs, orchestration, validation, and deployment. Shared contracts reduce integration errors and keep secrets server-side.
Seller experienceTailwind CSS, React FlowFast responsive UI and an interactive, readable competitive signal graph with unread evidence indicators.
Agent orchestrationCustom TypeScript modulesThe workflow is bounded and evidence-first, so explicit code paths, typed handoffs, and deterministic gates are easier to inspect and test than a free-form agent graph.
Search and retrievalYou.com Search API, FirecrawlLive company-specific discovery plus clean public-page extraction for the evidence ledger.
ReasoningOpenAI Responses APIConstrained claim extraction, grounded Q&A, and optional cited deep research in one provider API.
Data and control stateRailway PostgreSQL, Drizzle ORMDurable run, source, claim, lock, and rate-limit records with typed data access.
HostingRailwayManaged container deployment, environment variables, health checks, public domain, and managed PostgreSQL.
Why not n8n, LangGraph, or Python? n8n is excellent for simple integration automation but is not the best fit for this custom interactive product and evidence model. LangGraph is valuable for larger dynamic state graphs, but Intellia’s bounded pipeline is more transparent as typed application code. Python is strong for data science; here it would split the web product stack without a material advantage. The architecture can add a worker queue, Python analytics, or a graph framework later if scale warrants it.

8. Human handoff and success measure

Intellia is read-only and evidence-led. Sellers retain judgment before using positioning or claims in a deal; every output exposes source links and caveats. The system does not send messages, modify customer systems, make purchases, delete records, or externally publish information.

Success measure: a seller can produce a reviewable, company-specific competitive brief for a live market set in one run, with evidence, quality checks, and source traceability rather than unsupported assertions.
